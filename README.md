## Для чего нужен 365.

Чтобы понимать, что сделать сегодня, поддерживать привычки и сохранять важное — без перегруженных рабочих пространств. Задачи, календарь, здоровье, личные финансы, заметки и цели находятся рядом, а интерфейс помогает сосредоточиться на текущем дне.

**Новый аккаунт полностью пустой.** Никаких выдуманных показателей, примеров транзакций или автоматически созданных задач. Вы добавляете только свои данные.

## Возможности

| Раздел        | Что можно делать                                                                                      |
| ------------- | ----------------------------------------------------------------------------------------------------- |
| **Сегодня**   | Видеть дела, привычки и расписание на день; быстро добавлять задачи и следить за реальным прогрессом. |

## Сайт на GitHub Pages

**[delivery12335.github.io/365.---life-management](https://delivery12335.github.io/365.---life-management/)**

**Полная бесплатная облачная версия:** подключите Supabase Free по [инструкции](docs/SUPABASE.md). Тогда регистрация, вход и записи работают прямо по ссылке GitHub Pages: интерфейс размещён на GitHub, аккаунты и PostgreSQL — в Supabase. Приватность обеспечивают RLS и функции базы с проверкой владельца и версии записи. Для этого не нужен платный Node.js-сервер.

Без переменных подключения Supabase Pages публикует **презентационную версию интерфейса**: можно посмотреть оформление, переключить язык и тему. Вход и регистрация отключены, данные аккаунта не собираются.

GitHub Pages не исполняет Node.js и не размещает SQLite API. Выберите Supabase для облачной версии или Node.js/SQLite для локальной. Workflow автоматически проверяет проект, собирает интерфейс с правильным путём репозитория и публикует его после изменений в `main`.

## Быстрый старт

Нужны **Node.js 22.13+** (ветка 22), 24 LTS или 26+ и npm.

```bash
git clone https://github.com/delivery12335/365.---life-management.git
cd 365.---life-management
npm ci
npm run dev
```

Откройте **http://127.0.0.1:5173/** и создайте свой аккаунт. Одна команда запускает Vite и API на порту `3001`. Node.js 22 может выводить уведомление об экспериментальном SQLite API.

| Команда                         | Назначение                                           |
| ------------------------------- | ---------------------------------------------------- |
| `npm run dev`                   | Локальная полная версия: интерфейс + API.            |
| `npm run build`                 | Проверка TypeScript и production-сборка.             |
| `npm start`                     | Раздача `dist/` и API одним Node.js-сервером.        |
| `npm run build -- --mode pages` | Статическая презентационная сборка для GitHub Pages. |

`npm run preview` показывает только статические файлы; сервер аккаунтов эта команда не запускает.

## Ваши данные

В облачном режиме записи находятся в Supabase PostgreSQL и защищены владельцем аккаунта. Supabase SDK сохраняет токены сессии в sessionStorage, а с «Запомнить меня» — в localStorage. Сроки и обновление облачных сессий определяет Supabase Auth. Публичный ключ не даёт доступа к чужим записям; secret/service_role ключи блокируются проверкой сборки. Почтовое восстановление требует настроенного SMTP в Supabase.

Полная версия хранит записи в **SQLite на сервере**, отдельно для каждого аккаунта. В браузере сохраняются только предпочтения языка и темы; личные записи в localStorage не кэшируются и старые анонимные данные в аккаунт не импортируются.

- Пароли хешируются с индивидуальной солью через `scrypt`.
- Сессии используют HttpOnly / SameSite cookies; в базе лежат хеши токенов.
- Обычная сессия действует до 8 часов, «Запомнить меня» — до 7 дней.
- Каждый запрос проверяет владельца аккаунта. Сохранения защищены от конфликтов версий.
- Восстановление использует одноразовую ссылку на 30 минут и отзывает старые сессии после смены пароля.
- Данные `.data/`, база SQLite, локальные письма и `.env` не включаются в репозиторий и Pages.

Финансовые и медицинские записи вводятся вручную: приложение не подключено к банкам и медицинским устройствам. Отсутствующие измерения остаются пустыми.

## Развёртывание

Для **полноценного приложения** нужен Node.js-хостинг с постоянным диском:

1. Выполните `npm ci` и `npm run build`.
2. Создайте `.env` в корне проекта по [docs/.env.example](docs/.env.example).
3. Укажите `NODE_ENV=production`, `APP_ORIGIN=https://ваш-домен`, `HOST=0.0.0.0` и абсолютный `DATABASE_PATH` на постоянном диске.
4. Запустите `npm start` за HTTPS reverse proxy. Production использует Secure `__Host-` cookies и требует HTTPS origin.
5. Настройте согласованные резервные копии SQLite, учитывая WAL/SHM, и доступ к файлам только для процесса сервера.

### Письма восстановления

Для реальной отправки задайте `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_USER`, `SMTP_PASSWORD`, `MAIL_FROM` в `.env`. Секреты должны оставаться только на сервере; переменные `VITE_*` для них использовать нельзя.

**Без SMTP в режиме разработки** ссылка сохраняется как локальный файл `.eml` в `.data/mail`. Письмо не отправляется в интернет. В production восстановление без SMTP недоступно. Подтверждение email, OAuth, MFA и удаление аккаунта пока не реализованы.

## Как устроен проект

```text
365/
├── frontend/           # интерфейс приложения
│   ├── src/            # страницы, компоненты, авторизация, стили и типы
│   ├── public/         # статические файлы
│   ├── index.html      # входная HTML-страница
│   ├── vite.config.ts  # сборка и разработка
│   └── tsconfig.json   # настройки TypeScript
├── backend/            # локальный сервер и облачная схема
│   ├── app.mjs         # HTTP API, авторизация и SQLite
│   ├── index.mjs       # запуск сервера
│   ├── mail.mjs        # отправка писем
│   ├── validation.mjs  # проверка записей
│   └── supabase/       # схема PostgreSQL и политики доступа
├── docs/               # инструкции и пример настроек окружения
├── scripts/            # запуск разработки и проверка конфигурации
├── .github/            # автоматическая публикация сайта
├── .gitignore
├── package.json        # зависимости и команды проекта
├── package-lock.json   # точные версии зависимостей
└── README.md
```

## Проверка сборки

`npm run build` проверяет TypeScript и создаёт production-сборку. GitHub Actions собирает облачную версию перед каждой публикацией. В браузер допускается только публичный ключ Supabase; секретные ключи блокируются проверкой конфигурации.
